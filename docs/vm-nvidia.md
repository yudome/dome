# NVIDIA VM backend

TLDR: `backend=auto` uses Conduit on an NVIDIA host when it can, otherwise the QEMU GL path.

## Check

```bash
yudae vm doctor          # human JSON
xmake doctor             # host + vm checks
xmake doctor --json      # machine readable vm checks
```

Each failing check prints a fix. Agents run `yudae vm doctor`, not install commands.

## Backends

- `nvidia`: Conduit backend + `conduit-guest` + patched QEMU, real host GPU.
- `gl`: current virtio-gpu/virgl path.
- `auto`: NVIDIA if the capability probe passes, else GL. `--gl` forces GL.

The NVIDIA guest has no virtio-gpu. Its compositor uses `/dev/dri/card*` from the
Conduit module; `yudae-session` selects the card from `/dev/dri/by-path`.

## QEMU

The source fork is `yumedots/qemu-linux`, `main` = QEMU v11.1.2 + Conduit's nine
patches as commits. The daemon prefers the local Conduit build
`~/qemu-linux/install/bin/qemu-system-x86_64` (it has the `alsa` backend the
audio bridge needs), then the installed
`/opt/conduit/bin/qemu-system-x86_64`. Override with `YUDAE_NVIDIA_QEMU`. Both
need the Conduit device (`vhost-user-test-device-pci`); the local build uses
`--enable-alsa --enable-pa --audio-drv-list=alsa,pa`.

## ABI

620.70.06 tables live in `yumedots/conduit` from Conduit's generators. New
releases are generated by Conduit's weekly ABI workflow; run its generator when
the host driver is newer. `conduit-backend --allow-nearest-abi` covers the escape
table when an exact release table is not available.

## Golden image

`vm/packages.txt` is the explicit guest manifest. Build:

```bash
xmake vm packages --snapshot 2026/11/01 --force
xmake vm golden --snapshot 2026/11/01
```

The golden setup installs `conduit-guest`, matching headers, the NVIDIA mount,
the GBM link and `yudae-session`.

## Display

`yudae vm view` opens the VM app, whose `VmDisplay` item implements the broker
side of the Conduit display protocol (`shell/native/src/brokerdisplay.cpp`):
it listens on the backend's `display-nvidia.sock`, sends `EV_HELLO`/`EV_SURFACE`
and input events, and imports each ATTACH dma-buf with EGL zero-copy. One 40-byte
command per `recvmsg` keeps the SCM_RIGHTS fd bound to its ATTACH.

Clipboard: the broker advertises `CAP_CLIP_LARGE`. Host text goes to the guest as
`EV_CLIPBOARD` chunks when the display gains focus or the host clipboard changes
while focused (up to 256 KiB); guest text arrives as `CMD_CLIPBOARD` chunks (up to
1 MiB) and is set on the host clipboard. The guest side is `conduit-clipboard-agent`
from `conduit-guest`.

Input: the host cursor is hidden over the display; the guest draws its own into
the frame. Hyprland's aquamarine does not declare
`DRM_CLIENT_CAP_CURSOR_PLANE_HOTSPOT`, so Conduit's cursor plane is never used and
`CAP_CURSOR` is not advertised. Host shortcuts are inhibited while the pointer is
over the display, so SUPER binds reach the guest. Ctrl+Alt+G locks the pointer
(`zwp_locked_pointer_v1` + relative motion as `EV_REL` under `EV_GRAB`) and
toggles it back; losing window focus also unlocks.

Wallpaper: the host wallpaper directory is shared as virtiofs tag `wallpaper`, and
`vm/desktop` mounts it and runs `awww` once Hyprland is up. NVIDIA guests run
`2560x1440@240` at scale `1.6667` (the Conduit mode list has no `1536x864`).

The external `conduit-viewer` is only a manual fallback; it is not started by
`yudae vm view`. `vm screenshot` uses guest `grim`, so it works without a viewer.

## Guest session

`yudae-desktop` runs `yudae-gpu-wait` first: on a Conduit guest (PCI `0x106d`) it
waits for the `0010:01:00.0` DRM card and the `/mnt/nvidia` share, mounts the share
if needed and links the NVIDIA GBM backend. Without it a second VM booting under
load could start Hyprland before the share was mounted (`CBackend::create()
failed`). The unit restarts on failure. `backend.log` in the VM run directory holds
the Conduit backend log.

`yudae-session` exports the NVIDIA EGL vendor and external-platform directories:

```sh
__EGL_VENDOR_LIBRARY_FILENAMES=/mnt/nvidia/share/glvnd/egl_vendor.d/10_nvidia.json
__EGL_EXTERNAL_PLATFORM_CONFIG_DIRS=/mnt/nvidia/share/egl/egl_external_platform.d:/usr/share/egl/egl_external_platform.d
```

Without the second variable Qt reports `qt.qpa.wayland: EGL not available`,
fails to create an RHI context, and Quickshell creates no layer surfaces. The
bar and wallpaper then stay black even though Hyprland and the guest GPU work.

## Lifecycle

- Memory budget: `budget.zig` allows three quarters of the host's current
  `MemAvailable`, clamped to `MemTotal - 1 GiB`. A 16 GiB host fits two 4 GiB VMs.
- `yudae vm snapshot <name> <tag>` on a running VM takes a disk-only internal
  snapshot through QMP (`blockdev-snapshot-internal-sync` on `disk0`). It is
  block-consistent, not RAM-inclusive; `restore` still needs the VM stopped.
- `yudae vm fork <new> --from <name>` works against a running source: the disk is
  copied with `qemu-img convert -U`. The copy is a live-disk image, so treat it as
  crash-consistent.
- Conduit sets a migration blocker, so full savevm/RAM snapshots are not offered.

## Audio

Both backends attach an output-only Intel HDA card (`ich9-intel-hda` plus
`hda-output`). With the `snd-aloop` kernel module loaded
(`/etc/modules-load.d/yudae-audio.conf`), QEMU runs with `-audiodev
alsa,id=snd0,out.dev=yudaeN` and a per-VM `vm/asound.conf` alias:
`hw:Loopback,0,N` playback, paired with `hw:Loopback,1,N`. A small
`vm/audio-bridge` process reads that capture side and feeds the private
`yudae-vm` sink through `pacat`.

The guest is never a PipeWire client: its audio goes through the ALSA loopback,
so a PipeWire restart only affects the bridge, which reconnects by itself. QEMU
never appears as an output or application in the desktop audio graph; the
WirePlumber rule `config/wireplumber` disables the ALSA Loopback card and hides
the VM nodes, and the shell's audio lists skip `yudae-*`.

`yudae-vm` is a private null sink, so a VM that is not being viewed is silent.
`yudae vm view` loads a `module-loopback` from `yudae-vm.monitor` to the current
default sink; `release`, a normal window close, or a stopped VM unloads it. The
daemon watches the PulseAudio socket with inotify and recreates the sink and
loopback after a server restart; a 30 s safety pass covers module loss and the VM
app window (clearing the selection after a 20 s grace if the app was killed).

If `snd-aloop` or QEMU's `alsa` backend is missing, the daemon falls back to
`-audiodev pa` (and then `none`). The `pa` fallback does not reconnect after a
host PipeWire restart; the ALSA path does. The guest never captures the host
microphone (`hda-output`).
